In one sentence

It adds safety rules to database logins, a bit like a bank card that is blocked after too many wrong PINs and has to be renewed every so often.

How the real project is different

The real project is a proof of concept from my Taiwan Mobile internship, built with PostgreSQL, Bash, C, and Linux as a lower-cost alternative to a commercial tool. It adds stronger password rules, locks an account after 3 wrong passwords, and makes passwords expire after 90 days. It was tested in a test environment, not used in production. PostgreSQL can make a password expire with VALID UNTIL, but it doesn't lock an account after failed logins by itself; that is one of the rules this proof of concept adds. The exact rules it checks are in the repo; the rules and commands on this page are only examples.

What I learned

  • How to compare a lower-cost approach with a commercial tool, and what a proof of concept needs to show to be useful.
  • I asked my mentor if I could take this project.
  • The hardest part was lockout. PostgreSQL does not count failed logins by itself, so I wrote a Bash script that reads the logs every 5 minutes and counts failures for each user.
  • I also had to decide when the count goes back to zero: after a successful login, a password change, or an unlock.
  • Why changes are tested in a test environment first. This proof of concept was tested there and was not used in production.

Mini glossary

Password policy
A set of rules a password must follow, like a minimum length.
Account lockout
Blocking an account after too many wrong passwords, to stop guessing.
Password expiry
A password stops working after a set time (here, 90 days). In PostgreSQL this is the VALID UNTIL date on a role.
Brute-force attack
Trying password after password until one works.
Role
PostgreSQL's word for a user account. CREATE ROLE makes one, ALTER ROLE changes it.
Test environment
A separate copy of a system used for trying changes safely, away from real users.
