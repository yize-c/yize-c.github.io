SecureText: End-to-End Encrypted Chat

View the code on GitHub ← Back to projects

In one sentence

It lets two people chat so that only they can read the messages, like putting a note in a locked box that only Alice and Bob have keys to, and handing it to a mail carrier (the server) who can carry the box but can't open it.

      How the real project is different

      The real SecureText is a chat program that runs in the terminal, written in Python. Besides encrypted messages (ECDH + AES-GCM), it has safer password storage, two-factor login, GitHub login, and user roles. Every push runs 22 tests, a Bandit security check, and my dependency scanner in GitHub Actions. This page only shows the encryption idea.

      What I learned

      • How end-to-end encryption works in practice: the server only passes along scrambled messages, and only Alice and Bob can unlock them (ECDH + AES-GCM).
      • Starting from an intentionally insecure version and adding one protection at a time: encryption, safer password storage, two-factor login, GitHub login, and user roles.
      • How to run 22 tests, a code security check (Bandit), and my own dependency scanner on every push with GitHub Actions.

      Mini glossary

      End-to-end encryption
      Only the sender and the receiver can read a message. Servers in the middle only see scrambled text.
      Public / private key
      A matching pair of keys. The public key can be shared with anyone; the private key must stay secret.
      ECDH
      A way for two people to create the same secret key over a public connection, without ever sending the key itself.
      AES-GCM
      A fast encryption method that also detects if the scrambled message was changed on the way.
      Two-factor login (2FA)
      Logging in needs your password plus a second thing, like a code from an app on your phone.
      Bandit
      A tool that scans Python code for common security mistakes.
